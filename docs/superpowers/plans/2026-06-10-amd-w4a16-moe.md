# AMD W4A16 (compressed-tensors INT4) MoE Implementation Plan

> **For agentic workers:** TDD, op-test first. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Serve compressed-tensors INT4 (W4A16, group_size=32, symmetric, pack-quantized)
MoE models on AMD/ROCm (gfx942) — the routed-expert quantization used by Kimi-K2.6.

**Architecture:** Two phases. Phase 1 dequantizes INT4 experts → bf16 at load and reuses
the already-validated bf16 Triton MoE (no kernel change) — fast correctness baseline +
op-test oracle. Phase 2 implements true in-kernel INT4 dequant in `fused_moe_kernel`
(keeps the 4× smaller footprint), validated against Phase 1.

**Tech Stack:** Triton MoE (`tokenspeed_kernel.ops.moe.triton`), compressed-tensors
quant schemes, MoE backend registry/selector.

**Context (verified):**
- Kimi-K2.6 quant: only the 384 routed experts are INT4; attention/shared-experts/dense
  MLP/lm_head/vision are bf16 (config `ignore` list). `format: pack-quantized`,
  `num_bits 4`, `group_size 32`, `symmetric` (no zero-points), `type: int`.
- Packed layout (compressed-tensors): qweight `[out, in//8]` int32 (8 int4 along `in`);
  scales `[out, in//group_size]`; no zeros (symmetric).
- `use_int4_w4a16` already threads through `fused_moe_kernel`/`invoke_fused_moe_kernel`
  but the kernel has NO int4 dequant (loads raw bytes → `tl.dot`). Stub.
- MoE backend ABC: `supports / create_layer_weights / process_weights_after_loading /
  forward` (`backends/base.py`). Marlin wna16 backend is the NVIDIA template
  (`backends/wna16/marlin.py`, `Wna16MarlinBackend`).
- Selector maps `"wna16": ("marlin",)`; AMD branch handles only unquantized/fp8/
  w8a8_fp8/mxfp4 (`moe/core/selector.py`).

## Phase 1 — dequant-on-load → bf16 (working baseline)

### Task 1: INT4 unpack/dequant utility + CPU unit test
**Files:**
- Create: `python/tokenspeed/runtime/layers/quantization/compressed_tensors/w4a16_dequant.py`
- Test: `test/aiter/test_w4a16_dequant.py`

- [ ] Write failing CPU test: pack a known `[out,in]` bf16 weight to INT4 group-32 symmetric
  (compute per-group absmax scale, quantize to [-8,7], pack 8 nibbles/int32 along `in`),
  call `dequantize_w4a16(qweight, scales, group_size=32)`, assert it reconstructs the
  quantized-then-dequantized weight within group rounding error.
- [ ] Implement `dequantize_w4a16(qweight_packed[out,in//8] int32, scales[out,in//group] ,
  group_size) -> bf16[out,in]`: unpack nibbles (`(x >> 4*i) & 0xF`, sign-extend from uint4
  via `- 8` for symmetric uint4b8, or interpret as int4), reshape to groups, multiply by
  per-group scale, return bf16. Pure torch, device-agnostic.
- [ ] Run on CPU, verify pass. Commit.

## Phase 2 — in-kernel INT4 (footprint-preserving, optimization)

### Task 5: INT4 op-parity test (synthetic) vs Phase-1 dequant oracle
- [ ] `test/aiter/test_w4a16_moe_kernel_amd.py`: random experts, pack INT4+scales, run

### Task 6: Implement INT4 dequant in `fused_moe_kernel`
**Files:** Modify `tokenspeed-kernel/python/tokenspeed_kernel/ops/moe/triton.py`
- [ ] In `triton_forward`/`build_triton_gemms`, set `use_int4_w4a16=True` for the wna16
  in-kernel backend and pass group scales `[E, K//group, N]` as `B_scale` + group_k.
- [ ] In the kernel K-loop (require `BLOCK_SIZE_K % group_size == 0`): load packed b int32,
  unpack 8 nibbles → int values, load per-K-group `b_scale` (mirror the fp8 block-wise
  `offs_ks = k_start // group_k` path), dequant `b = (unpacked - 8).to(compute_type) *
  b_scale`, `tl.dot(a, b, acc=accumulator)`. Handle the packed b stride/pointer math.

### Task 7: In-kernel wna16 backend + wire selector
- [ ] `Wna16TritonBackend` keeping packed weights (no dequant); selector AMD wna16 ->
  prefer `triton` (in-kernel), fall back to `triton_dequant`. Re-run Tasks 4-5.

## Notes / risks
- Pack order must match between Task-1 dequant, Task-3 quantizer, and Task-6 kernel — pin
  with the op-test before any serve.
- gqa constraint (AITER MLA decode): choose attn_tp so num_heads/attn_tp ∈ {8,16,...}.
- Kimi on beverin still needs multi-node transport (separate workstream); Phase 1 bf16
  dequant fits 8 nodes, Phase 2 INT4 fits ~2 nodes.
